## Decisions & gate outcomes

- **Combined ORM + auth sprint (human-directed).** Sprint 02 delivers both the
  persistence rebuild and the auth replacement in a single pass; auth is written
  once on the ORM rather than twice.
- **Stack (human-approved):** async SQLAlchemy 2.0 (`aiosqlite`), full
  async-first conversion, Alembic migrations; fastapi-users 15.0.5. Python 3.12
  retained (3.14 retarget considered and dropped — 3.12 not EOL).
- **Auth backend:** fastapi-users `DatabaseStrategy` + `CookieTransport`
  (HttpOnly `session` cookie) — server-side sessions with a fixed absolute
  lifetime (default 7 days, `COMPANY_HUB_SESSION_TTL` override), immediate
  server-side revocation on logout. Resolves the sprint01 "sessions have no
  expiry" limitation.
- **Accounts:** stable persisted admin credential (generated-and-printed once or
  `COMPANY_HUB_ADMIN_PASSWORD`; not re-randomized per restart); additional
  accounts superuser-created via API only (`POST /api/auth/users`) — no
  self-service signup, no SPA admin UI this sprint. `me` now returns
  `{id, email, is_superuser}`.
- **SSO readiness (human-approved):** `oauth_accounts` table added now
  (schema-only, Google-oriented); no OAuth routes this sprint.
- **Contract continuity:** login keeps the JSON `{email, password}` body (custom
  router over fastapi-users components; response is now `{access_token,
  token_type}` + `session` cookie); logout idempotent `204`.
- **Migrations:** baseline reproduces the Sprint 01 schema verbatim; sprint02
  revision alters `users`, drops `sessions`, adds `access_tokens` +
  `oauth_accounts`. One-time `data/` flush performed (scope item n).
