## Decisions & gate outcomes

- **Role model (human-directed):** accounts carry `access_level`
  guest < read-only < user < admin; admin = former superuser. Guest sees an
  empty/blocked view; read-only views but does not mutate (incl. document
  generation as a write, denied); role replaces `is_superuser` (migration 0003
  maps 1→admin, 0→user, drops the column).
- **SSO provisioning (human-directed):** Google SSO auto-provisions an account
  at **guest** level on first sign-in for an unknown email; a known email links
  to the existing account (by `oauth_accounts`, then by email).
- **Admin user management (human-directed):** full CRUD under
  `/api/auth/users{/id}` with guardrails — last admin cannot be demoted/deleted;
  the bootstrap admin is permanently protected (never deactivated/demoted/
  deleted); admins cannot change their own level.
- **SSO enablement (human-directed):** opt-in via
  `COMPANY_HUB_GOOGLE_CLIENT_ID` / `COMPANY_HUB_GOOGLE_CLIENT_SECRET`; login
  button shown only when enabled (public `GET /api/auth/providers`).
- **SSO verification (human-directed):** manual-only against real Google
  credentials; no automated SSO checks.
- **Nav fix (human-directed):** hide the entire top `<nav>` when unauthenticated.
- **Cookie security:** new `COMPANY_HUB_SECURE_COOKIES=1` makes the session
  cookie Secure (production); default off for dev-over-HTTP. OAuth state secret
  from `COMPANY_HUB_OAUTH_STATE_SECRET` (fallback: Google client secret).
- **Custom SSO callback:** reuses `UserManager.oauth_callback` + the same
  `DatabaseStrategy`/`CookieTransport`, sets the session cookie, 302→`/`.
